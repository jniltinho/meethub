# Proposal

## Why

Messages are text only: people cannot share a document, a screenshot or a log, and the approved layout has two empty
places waiting for files — the channel header's Files button and the recent files of the details panel — plus a Files
section that is still a placeholder. Attachments are the next piece of the chat, and Mattermost's file model (uploads
that become part of a post) is the functional base.

## What Changes

- **Uploading and attaching**: a member uploads files to a channel and attaches up to 10 to a message; a message may
  be files alone. Defaults: 50 MiB per file, both limits configurable.
- **Downloading**: members of the file's channel download it; everyone else gets "not found". Files are always
  served as downloads, never rendered by the browser from MeetHub's origin.
- **Images**: PNG, JPEG and GIF get a thumbnail and a preview generated by the server; they show inside the message
  and open enlarged, and the original stays available to download.
- **Storage**: two drivers chosen by configuration — a directory on the server (the default) and an S3-compatible
  service (MinIO, AWS S3) for several replicas; credentials only through the environment.
- **Lifecycle**: deleting a message removes its files; uploads never attached are removed after 24 hours.
- **Channel files**: the header's Files button lists the channel's files in the side panel, and the details panel
  shows the most recent ones.
- **Files page**: the Files section lists the files of every channel the user belongs to, with a search by name.
- **Composer**: an attach button, dropping files on the conversation and pasting images, with per-file progress,
  removal and retry.

Assumptions (the three scope questions went unanswered, so the recommended options are taken; each can be struck
before implementation): both storage drivers; 50 MiB and 10 files per message; thumbnails, channel files, the Files
page and drag-and-paste are all in scope.

Out of scope: virus scanning, previews of PDFs, office documents, audio or video, searching inside files, file
names in the message search, editing a message's attachments after it is sent, quotas per user or team, public
links, and the meeting elements of the layout (`add-livekit-meetings`, running in parallel).

## Capabilities

### New Capabilities

- `file-attachments`: uploading files to a channel, attaching them to messages, who may download them, their
  lifecycle, and the lists of a channel's and a user's files.
- `file-storage`: where file bytes live — the storage drivers, their configuration and what a deployment must
  provide.
- `file-previews`: the thumbnails and previews the server derives from images, and their limits.

### Modified Capabilities

- `messages`: a message may carry files and may then have no text; its projection lists them.
- `chat-ui`: attaching in the composer, files inside messages, the channel's files in the side panel and the
  details panel.
- `web-shell`: Files is no longer a placeholder section.
- `configuration`: the file settings and their secrets.
- `background-jobs`: a scheduled task removes uploads that were never attached and the bytes of deleted files.

## Impact

- **Database**: migration `00004` on the three dialects (`file_infos`); `00005` is reserved for the meetings change.
- **API** (`/api/v1`): `POST /files`, `GET /files/:id` (and `/thumbnail`, `/preview`, `/info`),
  `GET /channels/:id/files`, `GET /users/me/files`; `POST /posts` accepts `file_ids`; posts carry `file_ids` and
  `metadata.files`. `docs/api.md`, `docs/deployment.md` and `docs/security.md` change with them.
- **Backend**: a new `internal/files` package (model, service, storage drivers), `internal/chat` (posts with files),
  handlers, configuration, an Asynq task; the image scaling of `internal/identity/picture.go` moves to a shared
  package. One new dependency: an S3 client (`github.com/minio/minio-go/v7`).
- **Deployment**: the Compose stack keeps files on the `meethub-data` volume by default; an optional MinIO service
  for the S3 driver in the test stack.
- **Frontend**: composer, message item, a files panel, the details panel, the Files page, the chat store, catalogs,
  contrast recipes and gallery entries.
- **Parallel work**: `add-livekit-meetings` runs in its own branch and touches the same layout files; this change
  keeps its edits there additive.
