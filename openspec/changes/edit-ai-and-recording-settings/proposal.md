# Proposal

## Why

Setting up meeting summaries today means editing two files on the server: the key in `.env` and the models in
`config.toml`. In Administration → Settings every `ai.*` row, and `recordings.retention_days`, `ffmpeg_path` and
`dir`, are read-only, so the owner who was just given an API key has nowhere to put it. The check against OpenAI
(task 4.2 of `add-meeting-summaries`) also showed that the documentation does not say which models work.

## What Changes

- **The AI keys are entered in Administration.** Settings → Meeting summaries gains an "AI service" form with the
  key (and the optional transcription key): write-only, shown as set or not set, replaceable and removable. They
  are stored encrypted with `MEETHUB_SECRET_KEY` in the database, take effect at once on every server without a
  restart, and work on every kind of install, including containers without the settings applier.
  `MEETHUB_AI_API_KEY` (or `_FILE`) still wins and then locks the field. A key in `config.toml` is still refused.
- **The other AI settings are editable** through the existing apply, restart and keep flow: `ai.base_url`,
  `ai.transcription.base_url`, `ai.transcription_model`, `ai.summary_model`, `ai.language`, `ai.timeout`,
  `ai.max_upload_bytes`, `ai.context_tokens`, `ai.max_output_tokens`.
- **Three more recording settings are editable**: `recordings.retention_days`, `recordings.ffmpeg_path` and
  `recordings.dir`. Recordings are not deleted by a new retention while its change waits for "Keep these
  settings", so a rollback loses nothing; `dir` is refused while a recording is in progress or being prepared.
- **Sensitive changes ask for the password again.** A change of where people's data is sent (the two AI
  addresses), of a key, of the retention or of the two paths needs the owner's current password, and a current
  authenticator code when two-factor is on. A stolen session alone can then neither point meetings at another
  server nor read out a key. This replaces the reason these settings were read-only.
- **Documentation**: a "Meeting summaries with OpenAI" walk-through (which models work: `whisper-1` for
  transcription, `gpt-4o-transcribe` does not return timed segments; summary models), every `ai.*` and
  `recordings.*` setting with its bounds and hint, where each is changed, and the security notes rewritten for
  the new rule.
- The settings page gives each of these settings a one-line hint.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `admin-settings`: the allowlist grows (AI settings, retention and the two recording paths); sensitive settings
  need the password again; retention waits for the confirmation; the AI keys are set from the page.
- `configuration`: `MEETHUB_SECRET_KEY` also protects the AI keys kept in the database; the configuration file is
  no longer the only store (the AI keys entered in Administration are in the database).
- `audit-log`: a key set, replaced or removed is audited without its value.

## Impact

- Code: `internal/config/admin.go` (allowlist, a URL kind), `internal/settings` (sensitive keys, reasons),
  `internal/org` and a migration (two encrypted columns), `internal/summaries` and `internal/ai` (the key read with
  the setting before every request), `internal/auth` (the seal moves to a shared place, password re-check),
  `internal/recordings` (expiry held during a pending change), handlers, `AdminSettingsView.vue`,
  `AdminSummariesView.vue`, the i18n catalogs.
- API: `GET` and `PUT /api/v1/admin/summaries/keys` (an empty value removes the key),
  `GET /api/v1/admin/settings/reauth` and `/retention`; `PUT /api/v1/admin/settings` takes `password` and `code`
  when a sensitive key is in the change (`403 reauth_required`, `reauth_failed`, `reauth_unavailable`).
- Docs: `docs/deployment.md`, `docs/admin-settings.md`, `docs/security.md`, `docs/api.md`, `docs/install-linux.md`,
  `config.toml.example`, `README.md`, `AGENTS.md` rule 4 (secrets: the environment, or the AI keys entered in
  Administration and stored encrypted).
- No new dependency. `MEETHUB_SECRET_KEY` becomes needed to enter a key in the page (it is already generated by
  `make init` and by the packages); without it the form says so and the environment variable remains the way.
